## 3. Ответы на контрольные вопросы

**1. Из каких секций состоит SELECT и в каком порядке они логически выполняются?**
Пишутся в порядке: `SELECT`, `FROM`, `WHERE`, `GROUP BY`, `HAVING`, `ORDER BY`, `LIMIT/OFFSET`. Логически выполняются так: `FROM` (источники и соединения) → `WHERE` (фильтр строк) → `GROUP BY` (группировка) → `HAVING` (фильтр групп) → `SELECT` (вычисление выражений, псевдонимы, `DISTINCT`) → `ORDER BY` → `LIMIT/OFFSET`. Поэтому псевдоним из `SELECT` нельзя использовать в `WHERE`, но можно в `ORDER BY`.

**2. Почему в промышленных запросах не рекомендуется `SELECT *`?**
Лишние столбцы увеличивают объём данных, нагрузку на сеть и память. Запрос ломается или меняет поведение при добавлении, удалении или перестановке столбцов. Мешает использованию покрывающих индексов (index-only scan). Скрывает, какие данные реально нужны приложению. Может раскрыть лишние (например, служебные или конфиденциальные) поля.

**3. Для чего `WHERE` и как комбинируются условия?**
`WHERE` оставляет только строки, для которых условие истинно (`TRUE`); строки с `FALSE` и `NULL` отбрасываются. Условия объединяются через `AND`, `OR`, `NOT`. Приоритет: `NOT`, затем `AND`, затем `OR`; порядок меняют скобками.

**4. Чем `BETWEEN` и `IN` отличаются от сравнений и `OR`?**
Это сокращённая запись. `x BETWEEN a AND b` равносильно `x >= a AND x <= b` (границы включаются). `x IN (a, b, c)` равносильно `x = a OR x = b OR x = c`. Результат тот же, но запись короче и читается лучше. С `NULL` осторожно: `NOT IN` со списком, содержащим `NULL`, не вернёт строк.

**5. Как работает `LIKE`?**
Сравнивает строку с шаблоном: `%` заменяет любую последовательность символов (в том числе пустую), `_` заменяет ровно один символ. `LIKE` чувствителен к регистру, `ILIKE` в PostgreSQL нет. Спецсимволы экранируются через `\` или `ESCAPE`.

**6. Что такое трёхзначная логика и почему нельзя писать `= NULL`?**
Результат условия может быть `TRUE`, `FALSE` или `UNKNOWN`. `NULL` означает «значение неизвестно», поэтому любое сравнение с ним (`x = NULL`, `x <> NULL`, даже `NULL = NULL`) даёт `UNKNOWN`, а `WHERE` такие строки отбрасывает. Для проверки используют `IS NULL` и `IS NOT NULL` (а для сравнения с учётом NULL — `IS [NOT] DISTINCT FROM`).

**7. Что делает `ORDER BY`?**
Сортирует результат по одному или нескольким выражениям. По умолчанию `ASC` (по возрастанию), для убывания пишут `DESC`, направление задаётся для каждого столбца отдельно. В PostgreSQL `NULL` считается наибольшим значением: при `ASC` идут в конце, при `DESC` в начале. Положение меняют через `NULLS FIRST` и `NULLS LAST`.

**8. Для чего `LIMIT` и `OFFSET`?**
`LIMIT n` ограничивает число возвращаемых строк, `OFFSET m` пропускает первые `m` строк. Для страницы с номером `N` и размером `S`: `LIMIT S OFFSET (N-1)*S`. Обязательна однозначная сортировка (например, по `id` вторым ключом), иначе страницы могут пересекаться. На больших смещениях `OFFSET` медленный (строки всё равно читаются), тогда применяют keyset-пагинацию (`WHERE id > последний_id`).

**9. Что делает `DISTINCT`?**
Удаляет из результата полностью совпадающие строки (по всем выбранным столбцам, `NULL` считаются равными между собой). Применяется после вычисления `SELECT`-списка. В PostgreSQL есть расширение `DISTINCT ON (...)`, оставляющее первую строку из каждой группы.

**10. Как сгенерировать большой объём тестовых данных в PostgreSQL?**
Функция `generate_series(start, stop[, step])` создаёт последовательность чисел или дат. На её основе строят `INSERT ... SELECT`, где значения вычисляются из номера строки: арифметика и `%`, конкатенация, `lpad`, выбор из массива `(ARRAY[...])[1 + g % N]`, `random()`, интервалы от `now()`. Внешние ключи берут из уже заполненных таблиц, а зависимые суммы пересчитывают через `UPDATE ... FROM` или `JOIN`.
